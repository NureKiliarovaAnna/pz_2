## 2. Дві найдорожчі функції

Середні значення до оптимізацій: **`createProposal` — 193 307**, **`execute` — 154 702** (далі `delegate` 95 699, `castVote` 88 647).

Середні з gas-reporter залежать від набору тестів, тому для порівняння «до/після» використано детермінований бенчмарк [`scripts/gas-benchmark.js`](../scripts/gas-benchmark.js) (однакові вхідні дані, опис «Fund the DAO website»). Результати: [`gas/before.json`](gas/before.json), [`gas/step1-uint48-packing.json`](gas/step1-uint48-packing.json), [`gas/after.json`](gas/after.json).

### Оптимізація 1 — пакування `snapshotBlock` і `deadline` у `uint48`

Було: `recipient`, `snapshotBlock` і `deadline` займали три окремі слоти по 32 байти. Стало: `address recipient` (20 байтів) + `uint48 snapshotBlock` (6) + `uint48 deadline` (6) = рівно один слот. `createProposal` записує на **два нульові слоти менше** (кожен запис нуль → не нуль коштує 22 100 газу), а `state()` читає один слот замість трьох.

`uint48` — стандартна ширина для моментів часу в OpenZeppelin (ERC-6372); переповнення виключене, приведення робиться через `SafeCast.toUint48`, який відкотить транзакцію, якщо значення не вміщається.

```solidity
struct Proposal {
    address proposer;
    bool executed;          // оптимізація 2
    address recipient;
    uint48 snapshotBlock;   // оптимізація 1
    uint48 deadline;        // оптимізація 1
    uint256 amount;
    ...
}
```

### Оптимізація 2 — `executed` в одному слоті з `proposer`

Було: `bool executed` стояв окремо, у власному нульовому слоті. `execute()` записував у нього `true`, тобто нуль → не нуль (22 100 газу). Стало: `executed` упакований поруч з `address proposer` (20 + 1 байт). Слот уже ненульовий, тому запис коштує 2 900 + 2 100 холодного читання, на ~17 тис. газу менше.

### Що розглянуто й відкинуто

- Зберігати замість опису лише його хеш, а текст віддавати тільки в події. Це дало б найбільшу економію для довгих описів, але `getProposals` перестав би повертати текст, і інтерфейсу довелося б індексувати події. Відкинуто, щоб не погіршувати функції читання.
- Зменшити `amount` і лічильники голосів до `uint128`. Додаткова економія на `castVote` невелика, а ризик обмежень зростає. Відкинуто.
